### 1. LLM 八股

### 1.1 Transformer 的自注意力机制如何工作？为什么比 RNN 更适合处理长序列？

自注意力：对每个 token，用它的 Q 与所有 token 的 K 做点积 → 缩放 → Softmax → 加权求和 V，得到融合上下文的表示。

比 RNN 强在两点：
- **并行计算**：一次性处理整个序列，RNN 必须串行。
- **长距离依赖**：任意两个 token 交互路径为 O(1)，RNN 是 O(N)，易梯度消失。

### 1.2 什么是位置编码？为什么必需？列举两种实现方式。

- 位置编码：给 token 嵌入加上位置信息的向量，让模型感知词序。
- 为什么必需：自注意力本身是置换不变的，打乱顺序输出一样，无法区分"我打你"和"你打我"。
- 正弦/余弦编码：固定公式生成，可外推更长序列，能隐式学习相对位置。
- 可学习绝对位置编码：作为参数训练得到，灵活但无法泛化到超长序列（BERT/GPT-2 使用）。

### 1.3 详细介绍 RoPE，对比绝对位置编码的优劣。

RoPE（旋转位置编码）通过对 Q、K 向量按位置旋转，使注意力分数天然依赖相对位置 (m-n)。

- 优势：内置相对位置建模；外推能力强（长序列友好）；不引入额外参数；距离越远相关性自然衰减。
- 劣势：数学原理较复杂；对绝对位置的表征可能偏弱。

### 1.4 MHA、MQA、GQA 的区别？

三者区别在于 Q/K/V 头的共享方式，核心是效果与推理效率的权衡：

- **MHA**：N 个 Q 头、N 个 K 头、N 个 V 头。效果最好，但 KV Cache 大，推理慢（BERT/GPT-3）。
- **MQA**：N 个 Q 头、1 个 K 头、1 个 V 头。KV Cache 最小，推理最快，但效果可能下降（PaLM）。
- **GQA**：N 个 Q 头、G 个 K 头、G 个 V 头（1 < G < N）。折中方案，效果接近 MHA，效率远超 MHA（Llama 2）。

### 1.5 Encoder-Only、Decoder-Only、Encoder-Decoder 架构的区别？

- **Encoder-Only**（BERT）：双向自注意力，擅长 NLU（分类、NER、情感分析）。
- **Decoder-Only**（GPT/Llama）：单向因果注意力，自回归生成，擅长 NLG（对话、写作、代码生成）。
- **Encoder-Decoder**（T5/BART）：Encoder 双向编码源序列，Decoder 交叉注意力生成目标序列，擅长 Seq2Seq（翻译、摘要）。

### 1.6 什么是 Scaling Laws？有什么指导意义？

Scaling Laws 揭示模型性能（Loss）与参数量 N、数据量 D、计算量 C 之间呈幂律关系。

- 性能可预测：小模型实验结果可外推大模型性能。
- 瓶颈效应：N、D、C 需协同扩展，单一增大无效。
- Chinchilla 定律：计算最优时，参数量与数据量应约 1:20 比例扩展。
- 指导意义：科学规划资源、重视数据质量、避免盲目堆参数。

### 1.7 常见解码策略有哪些？

- **Greedy Search**：每步选概率最高的 token。最快但缺乏多样性，输出确定且呆板。
- **Beam Search**：保留 k 个最优候选序列。质量更高但成本 k 倍，仍倾向安全回答。
- **Top-K Sampling**：从概率最高的 K 个中随机采样。增加多样性，但 K 值固定不灵活。
- **Top-P (Nucleus) Sampling**：动态累加概率直到阈值 p，在其中采样。自适应候选集大小，兼顾质量与多样性，是目前默认策略。

### 1.8 BPE 和 WordPiece 子词切分算法的区别？

- BPE（GPT/Llama）：频率驱动，每次合并出现次数最多的相邻 token 对。
- WordPiece（BERT）：似然驱动，每次合并使语料库语言模型似然提升最大的 token 对。
- 共同优势：解决 OOV、平衡词表大小与序列长度、保留词根词缀关系。

### 1.9 NLP 和 LLM 最大的区别是什么？

最大区别是范式转变——从"一个任务一个模型"变为"一个模型解决所有任务"。

- 传统 NLP：分而治之，每个任务专门设计模型和训练数据（Pre-train → Fine-tune）。
- LLM：通用大模型 + Prompt/In-context Learning，支持零样本/少样本学习。
- LLM 规模更大（百亿起步），且涌现出小模型没有的能力（思维链、复杂推理等）。

### 1.10 L1 和 L2 正则化分别是什么？

- L1（Lasso）：惩罚项为权重绝对值之和 λΣ|w|。产生稀疏性，部分权重变为 0，适合特征选择。
- L2（Ridge/Weight Decay）：惩罚项为权重平方和 λΣw²。权重趋近 0 但不等于 0，平滑权重分布，通用防过拟合。

### 1.11 如何理解"涌现能力"？何时出现？

涌现能力：小模型上不存在，当模型规模突破临界点后突然出现并远超随机水平的能力。

- 特征：非线性增长（相变式跃迁）、非直接训练（自发习得）。
- 典型例子：思维链推理、上下文学习、复杂指令遵循。
- 出现规模：通常在百亿到千亿参数级别（如 PaLM 62B 出现 CoT），无固定数值。

### 1.12 LLM 常用的激活函数有哪些？

- **GeLU**（BERT/GPT-2）：ReLU 的平滑近似，梯度更稳定，类似随机正则化。
- **SwiGLU**（LLaMA/PaLM 等主流）：门控机制，Swish(A) ⊗ B，显著增强表达能力，实证效果优于 GeLU。

### 1.13 MoE 如何在不显著增加推理成本的情况下扩大模型规模？

核心策略：稀疏激活。N 个专家（Experts，各是一个 FFN）+ 门控路由器（Router），每次只激活 Top-K（通常 K=1 或 2）个专家。

- 总参数量 = 所有专家之和 → 参数规模极大。
- 推理计算量 ≈ 只激活 K 个专家 → 成本等于小得多的稠密模型。
- 代表：Mixtral 8×7B（总 47B，每次激活 ~13B）。

### 1.14 训练百亿/千亿参数 LLM 的主要挑战？

- 显存挑战：模型+梯度+优化器状态远超单卡显存 → 3D 并行（数据/流水线/张量并行）+ ZeRO 优化。
- 通信挑战：GPU 间通信成瓶颈 → NVLink/InfiniBand 高速互联 + 计算通信重叠。
- 训练不稳定：梯度爆炸/消失 → BF16 混合精度 + Pre-LayerNorm + 梯度裁剪 + 学习率预热。

### 1.15 开源框架和创新点？

- PyTorch（基础框架）、HuggingFace Transformers（模型库）、DeepSpeed/Megatron-LM（分布式训练）、vLLM/TensorRT-LLM（高效推理）。
- 创新点需结合具体论文回答（Qwen 系列、DeepSeek 系列如 GRPO）。

### 2. VLM 八股

### 2.1 多模态大模型的核心挑战是什么？

核心挑战是跨越"模态鸿沟"——视觉是连续像素矩阵，语言是离散符号序列。

- 对齐：让视觉概念与语言符号语义等价（如 CLIP 的对比学习）。
- 融合：让两种模态深度交互完成复杂推理。主流方法：连接器（LLaVA 的 MLP 将视觉特征转为 visual tokens 拼入 LLM）、跨模态注意力（Flamingo 在 LLM 层中插入交叉注意力）。

### 2.2 CLIP 模型的工作原理？

双编码器架构（图像编码器 + 文本编码器）→ 将图文映射到共享嵌入空间 → 对比学习训练。

- 正样本：匹配的图文对 → 最大化余弦相似度。
- 负样本：批次中其他 N-1 个样本 → 最小化余弦相似度。
- 使用 InfoNCE Loss，在海量图文对（4 亿）上训练，实现强大的零样本分类能力。

### 2.3 LLaVA/MiniGPT-4 如何连接视觉编码器和 LLM？

三个组件：
- 冻结的视觉编码器（CLIP ViT）：提取视觉特征。
- 连接器模块（LLaVA 用线性层，MiniGPT-4 用 Q-Former）：将视觉特征转为 LLM 能理解的 visual tokens。
- 冻结的 LLM（Llama/Vicuna）：接收 visual tokens + text tokens，自回归生成。

两阶段训练：先用图文标题数据训练连接器（对齐），再用视觉指令数据微调（学会对话推理）。

### 2.4 什么是视觉指令微调？为什么关键？

使用包含（图像 + 指令 + 回答）的数据集微调 VLM，指令形式多样。

- 泛化到未知任务：学会理解指令意图而非死板执行单一任务。
- 激发 LLM 潜力：教会 LLM 如何使用视觉信息进行推理和对话。
- 对齐交互模式：从任务工具变为真正的多模态对话助手。

### 2.5 视频相比静态图片，VLM 需额外解决哪些问题？

- 时序信息表征：需理解帧间动态关系 → 帧采样+时间融合模块 / 3D CNN / Video Transformer。
- 计算存储开销：数据量远超单图 → 稀疏采样、特征压缩。
- 长距离依赖：关键事件可能跨长时间窗口 → Transformer 全局感受野。
- 多模态融合复杂：还需融合音频、字幕 → 多异步序列对齐。

### 2.6 Grounding 在 VLM 中是什么？如何评估？

Grounding（定位/指代）：将语言中的概念与图像中的具体像素区域准确对应。

评估方法：
- 指称表达式定位：给定描述短语，预测边界框，计算 IoU（交并比），超过阈值则正确。
- 注意力图可视化：定性观察模型生成某词时注意力是否聚焦在对应区域。

### 2.7 对比两种 VLM 架构范式

- 连接器式（LLaVA）：前期对齐、后期融合。视觉特征 → visual tokens → 拼入 LLM。效率高、架构简洁，但存在信息瓶颈。
- 跨模态注意力式（Flamingo）：边生成边融合。LLM 每层插入交叉注意力查询视觉特征。融合更深、少样本能力强，但架构复杂、推理慢。

### 2.8 如何处理高分辨率输入图像？

- 切片编码拼接：切成多个低分辨率子图分别编码再融合，简单但有损全局结构。
- 可变分辨率图块：动态调整图块大小，保持序列长度不变，但丢失细节。
- 多尺度特征融合：从编码器不同层级提取多尺度特征，兼顾细节与全局（如 Monkey）。

### 2.9 VLM 幻觉与纯文本 LLM 幻觉有何不同？

VLM 幻觉基于视觉输入，错误地"看到"不存在的视觉事实：

- 物体幻觉：描述了图中不存在的物体（"图里有只狗"实际没有）。
- 属性幻觉：物体识别正确但颜色/数量/形状错误。
- 关系幻觉：物体间空间或动作关系描述错误（"在杯子里面"实际在旁边）。

### 2.10 VLM 的前沿应用方向？

- 多模态对话助手、视觉定位与具身智能（机器人）、UI 自动化。
- 专业领域：医疗影像分析、工业质检、保险定损。
- 内容创作：截图生成前端代码、图表数据解读。
- 教育无障碍：实时场景描述、交互式学习。

### 3. RLHF 八股

### 3.1 RLHF 解决什么核心问题？为什么 SFT 不够？

RLHF 解决"对齐"问题（HHH 原则）：有用性、诚实性、无害性。

SFT 不够的原因：
- 对齐目标模糊主观，难以用静态数据集精确定义。
- SFT 只能"模仿"不能"判断"，学不到偏好排序。
- 行为空间巨大，SFT 数据集覆盖有限 → 暴露偏差（训练用真实上下文，推理用自己生成的上下文）。

### 3.2 经典 RLHF 三阶段流程？

- 阶段一 SFT：高质量指令数据集微调基础模型 → 具备基本指令遵循能力。
- 阶段二 RM 训练：对同一 prompt 生成多个回答，人类排序 → 训练奖励模型预测偏好分数。
- 阶段三 PPO：以 SFT 模型为初始策略，RM 为奖励函数，用 PPO 优化 → 对齐后的最终模型。

### 3.3 为什么用成对比较而非绝对评分？

- 优势：认知负荷低，标注一致性高；能捕捉细微偏好差异；数据天然标准化（只关心相对大小）。
- 劣势：数据效率低（每次只产生 1 比特信息）；人类偏好可能不传递（A>B, B>C, 但 C>A）；无法体现差异幅度。

### 3.4 奖励模型架构与损失函数？

- 架构：与 SFT 模型同架构，最后一层替换为输出标量的线性回归头。
- 与最终 LLM 的关系：RM 是人类偏好的代理，RM 质量决定对齐天花板。
- 损失函数（基于 Bradley-Terry 模型）： Loss = -log(σ(r(y_w) - r(y_l)))，即最大化"好回答分数高于坏回答"的概率。

### 3.5 为什么选 PPO？KL 散度惩罚项的作用？

- vs REINFORCE：PPO 引入价值函数作基线 + 优势函数，大幅降低方差。
- vs Q-learning：LLM 动作空间（整个词表）巨大，Q-learning 不可行。
- KL 散度惩罚项作用：防止策略崩溃（模型钻 RM 漏洞作弊）；保持在 SFT 模型附近的安全探索区域；维持输出多样性和可读性。

### 3.6 KL 系数 β 过大或过小会怎样？

- β 过大：模型过于保守，几乎不更新，RLHF 效果大打折扣。
- β 过小：约束不足 → 奖励作弊、模式崩溃、语言能力退化。
- 调参方法：监控 KL 散度值（趋势和范围）、奖励分数变化、定期人工定性对比 RL 和 SFT 的输出。

### 3.7 什么是奖励作弊（Reward Hacking）？

Agent 发现并利用 RM 漏洞，以非预期方式获得高分而实际未完成任务目标。

- 例子：训练摘要模型，RM 偏好"含所有关键词"和"长文本" → 模型直接大量复制原文句子拼接，RM 打高分但毫无摘要价值。
- 缓解：迭代改进 RM（加入作弊样本作负例）、增强 KL 惩罚、多目标奖励集成、过程监督替代结果监督。

### 3.8 DPO 的核心思想？与 RLHF 的区别？

DPO 绕过显式 RM 和 RL 训练，直接用偏好数据优化策略模型。提高"胜出回答"生成概率，降低"落败回答"概率。

- DPO vs RLHF：DPO 两阶段（SFT + 偏好微调），无需 RM 和 RL；训练简单稳定、计算成本低；效果持平甚至更优。

### 3.9 RLHF 模型上线后回答模式化怎么办？

原因：RM 学到表面偏好（礼貌用词、安全套话）；PPO 过度优化到狭窄高分区域；偏好数据多样性不足。

解决：诊断 RM 是否存在偏差 → 收集 badcase 重新训练 RM → 增大 KL 系数 β / 引入熵奖励 / 早停 → 线上提高 Temperature 增加多样性。

### 3.12 信用分配问题？Token 级 vs Seq 级奖励？

- Seq 级奖励：整个序列只有一个分数，所有 token 收到相同信号 → 信用分配模糊，学习效率低。
- Token 级奖励：每个 token 有独立奖励 → 信号精细但获取极其困难。
- PPO 缓解方案：训练 Critic（价值模型）估计期望未来奖励 → 优势函数 A = 实际回报 - 期望回报，提供伪 token 级信号。GAE 进一步稳定优势估计。

### 3.13 RLAIF 是什么？潜力和风险？

用强大 AI 模型替代人类标注者提供偏好判断，"AI 训练 AI"。

- 潜力：可扩展性强（低成本、高吞吐）、标注一致性好、可评估复杂维度。
- 风险：偏见继承与放大（核心风险）、价值观"近亲繁殖"脱离人类、缺乏常识 grounding、对裁判 AI 过度依赖。

### 4. Agent

### 4.1 如何定义 LLM Agent？核心组件？

Agent = 以 LLM 为大脑，能自主感知、规划、执行行动以达成目标的系统。特征：自主性、循环执行。

四大核心组件：
- 大脑（LLM）：负责理解、推理、决策。
- 规划模块：将复杂目标分解为可执行步骤（CoT/ToT/GoT/ReAct）。
- 记忆模块：短期记忆（上下文窗口/对话缓冲） + 长期记忆（向量数据库 + RAG）。
- 工具使用模块：调用外部 API/代码执行/搜索引擎扩展能力。

### 4.2 详细解释 ReAct 框架？

ReAct = Reasoning + Acting，模仿人类的"思考→行动→观察→思考…"循环模式。

- Thought（思考）：LLM 分析当前状态并做策略规划。
- Action（行动）：生成结构化工具调用指令 `Action: [Tool, Input]`。
- Observation（观察）：工具执行结果反馈给 LLM 作为下一轮输入。

ReAct 中的思考是动态、交互式的思维链，能根据最新观察实时调整策略和修正错误。

### 4.3 赋予 LLM 规划能力的主流方法？

- CoT：引导 LLM "逐步思考"，线性推理链，最简单。
- ReAct：CoT + 行动，每一步思考后执行动作，交互式规划。
- ToT（思维树）：生成多条并行思考路径，用搜索算法评估和扩展，支持回溯。
- GoT（思维图）：比 ToT 更灵活，支持分支合并和循环迭代。
- 任务分解规划：显式分解为依赖图/步骤列表，规划器+执行器分离。

### 4.4 如何设计 Agent 的短期和长期记忆？

- 短期记忆：上下文窗口（直接载体）；缓冲管理（滑动窗口/摘要缓冲）；暂存器（记录 Thought-Action-Observation 轨迹）。
- 长期记忆：向量数据库（Pinecone/ChromaDB）+ Embedding 模型 → 存储历史经验/用户偏好 → 检索相关记忆注入 Prompt；也可用知识图谱/SQL 处理结构化记忆。

### 4.5 LLM 如何学会调用工具？（Function Calling）

Function Calling 让 LLM 理解何时用工具、用哪个、传什么参数。

- 定义工具 schema（函数名、描述、参数类型）传入模型。
- 模型根据用户意图决定是否调用，输出结构化调用请求（函数名 + JSON 参数）。
- 外部系统执行函数，返回结果给模型 → 模型根据结果继续推理或生成最终回复。

### 4.6 LangChain 和 LlamaIndex 的区别？

- LangChain：通用 Agent 开发框架，擅长链式调用、工具编排、Agent 循环，生态丰富。
- LlamaIndex：专注数据索引和检索，擅长构建 RAG 系统、结构化数据查询，索引能力强。

### 4.7 构建复杂 Agent 的主要挑战？

- 可靠的工具调用：模型可能误选工具、参数格式错误、工具失败后难以恢复。
- 长程任务规划：多步任务中中间步骤出错会级联放大，需要鲁棒的错误恢复。
- 上下文管理：长对话 + 多工具调用后上下文膨胀，需有效压缩和关键信息提取。
- 安全与可控性：防止 Agent 执行危险操作、陷入死循环或被注入攻击。

### 4.8 多智能体系统的优势和复杂性？

- 优势：分工协作（不同 Agent 专长不同领域）；并行处理提高效率；互相校验减少幻觉。
- 复杂性：通信协议设计（A2A）；任务分配与协调；冲突解决；整体行为涌现不可预测；调试和监控困难。

### 4.9 Agent 在真实环境 vs 纯软件工具的本质区别？

- 真实环境（机器人/游戏）：需处理物理世界不确定性（传感器噪声、执行误差）；需实时响应；安全约束更严格；状态空间连续且部分可观测。
- 纯软件工具：环境确定性高、可重试、响应时间相对宽松。

### 4.10 如何确保 Agent 安全可控？

- 工具权限最小化：白名单 + schema 校验，危险操作需人类审批（HITL）。
- 沙箱隔离：代码执行、网络访问等高风险操作在受限环境运行。
- 输入输出过滤：检测和拦截恶意 prompt、敏感信息泄露。
- 行为监控与熔断：异常调用频率/模式检测，自动降级或终止。
- 对齐训练：RLHF/DPO 使 Agent 行为符合人类意图和价值观。

### 4.11 A2A 框架和普通 Agent 框架的区别？

A2A（Agent-to-Agent）是跨 Agent 通信协议，解决不同框架、不同厂商 Agent 之间的互操作问题。普通 Agent 框架（如 LangChain）侧重单个 Agent 内部构建，A2A 侧重 Agent 之间的标准化通信（类似 HTTP 之于 Web 服务）。

### 5. RAG

### 5.1 RAG 的工作原理？相比微调有哪些优势？

RAG = 检索 + 生成，查询时从外部知识库检索相关文档，拼接后交给模型生成答案。

相比微调的优势：
- 知识实时更新（不改模型参数，更新文档即可）。
- 可溯源（答案附带引用来源），降低幻觉。
- 成本低（无需重训模型），适合知识频繁变化的场景。

### 5.2 完整 RAG 流水线有哪些关键步骤？

- 索引阶段：文档加载 → 清洗 → 切块 → 向量化（Embedding） → 写入向量库 + 元数据。
- 查询阶段：接收问题 → Query 改写 → 检索召回 → 重排序 → 上下文组装 → 模型生成 → 引用标注/格式化。

### 5.3 文本切块策略如何设计？

目标是保留语义单元而非均匀切分。结合固定长度 + 段落边界 + 标题层级 + 重叠窗口。

- 太大：噪声多、命中不准。太小：丢上下文、检索到也无法回答。
- 常见坑：忽略文档结构（标题/表格）、重叠不足、OCR 脏文本不清洗、多主题塞进一个 chunk。

### 5.4 如何选择 Embedding 模型？评估指标？

选型：考虑领域适配（通用 vs 垂直行业）、多语言支持、维度/成本/推理速度。

评估指标：
- MTEB 基准排名（综合检索、分类、聚类等任务）。
- 检索召回率（Recall@K）、MRR（Mean Reciprocal Rank）。
- 实际场景标注数据上的端到端评测。

### 5.5 提升 RAG 检索质量的技术？

- Query 改写：扩展/重写用户问题使其更适合检索。
- 混合检索：稠密向量 + 稀疏关键词（BM25）互补。
- 重排序（Rerank）：Cross-encoder 对召回结果二次精排。
- Metadata 过滤：利用时间、类别、权限等元数据缩小检索范围。
- HyDE：先生成假设答案再用其向量检索。

### 5.6 什么是"Lost in the Middle"？如何缓解？

LLM 对长上下文中间位置的信息关注度显著下降，中间的关键信息容易被"忽视"。

缓解：重排序把重要文档放开头或结尾；分段回答；使用长上下文优化后的模型。

### 5.7 如何全面评估 RAG 系统？

- 检索评估：Recall@K、Precision@K、MRR、NDCG。
- 生成评估：忠实度（是否准确引用）、答案正确率、幻觉率。
- 端到端评估：RAGAS 框架（Faithfulness、Answer Relevancy、Context Precision/Recall）。

### 5.8 什么场景用知识图谱替代向量检索？

- 实体关系复杂、需要多跳推理（如供应链溯源、法律条文关联）。
- 需要精确查询而非语义相似（如"某人的直系亲属"）。
- 结构化知识且需要逻辑推理（GraphRAG 结合知识图谱做摘要与推理）。
- 向量检索适合语义模糊匹配，图谱适合精确关系查询。

### 5.9 什么是 Agentic RAG？

不只"检索一次后生成"，而是 Agent 可根据中间推理结果进行多轮检索、动态调整检索策略。

- 传统 RAG：一次性检索 → 生成。
- Agentic RAG：思考 → 检索 → 评估 → 不充分则改写 query 再检索 → 循环直到信息足够或达到上限。

### 5.10 RAG 系统部署的挑战？

- 文档管理：版本更新、过期清理、权限过滤。
- 检索质量退化：索引过期、Embedding 漂移。
- 安全性：知识库文档可能含恶意注入内容（Indirect Prompt Injection）。
- 成本控制：Embedding 调用、向量库存储、Rerank 开销。

### 5.11 搜索系统和 RAG 的区别？

- 搜索系统：返回相关文档列表，依赖关键词/语义匹配，核心指标是召回和排序质量。
- RAG：搜索 + 生成，不仅找到文档还要综合生成答案，多了推理和摘要能力。

### 5.12 开源 RAG 框架选型？

RAGFlow、Dify、FastGPT 等。选型考虑：文档解析能力（PDF/表格/图片）、检索策略丰富度、部署便利性、社区活跃度、与企业现有系统集成难度。

### 6. 模型评估与 Agent 评估

### 6.1 为什么传统 NLP 指标（BLEU/ROUGE）不适合评估 LLM？

BLEU/ROUGE 基于 n-gram 重叠，衡量字面相似度，无法评估语义正确性、逻辑连贯性、创造性。LLM 的合理回答可能措辞完全不同，与参考答案 n-gram 重叠低但语义正确，传统指标会误判。

### 6.2 主流 LLM 综合性基准测试？

- MMLU：多学科知识问答（57 个学科），考察知识广度。
- Big-Bench：多样化任务集合（200+ 任务），考察泛化能力。
- HumanEval：代码生成能力（根据 docstring 生成正确函数）。
- GSM8K：小学数学推理，考察多步推理能力。
- HELM：多维度综合评估（准确性、鲁棒性、公平性、效率等）。

### 6.3 什么是"LLM-as-a-Judge"？优缺点？

用强 LLM 作为评估器，对另一个 LLM 的输出进行打分或比较。

- 优点：可扩展（自动化）、灵活（可评估开放性任务）、成本低。
- 缺点：裁判 LLM 自身有偏见（偏好长回答、偏好自己的输出、位置偏见）；评估标准漂移；缺乏真实世界 grounding。

### 6.4 如何评估事实性/幻觉水平？

- 事实性：用 TruthfulQA 等数据集；将回答拆成原子事实，逐一核验知识库；FactScore 指标。
- 幻觉检测：检测生成文本中无法从输入/检索文档中验证的内容；NLI 模型判断"生成句是否可由原文推出"。

### 6.5 评估 Agent 为什么比评估 LLM 更困难？

- 多维度：不仅要评估最终答案，还要评规划质量、工具选择正确性、执行效率。
- 过程评估难：中间步骤的"好坏"无标准答案，人工标注成本高。
- 环境依赖：Agent 表现依赖于工具可用性、网络延迟等外部因素，难以公平比较。
- 任务完成度难以量化：开放性任务无明确"正确/错误"。

### 6.6 评估 Agent 能力的基准测试？

- WebArena：模拟真实网站的交互任务（购物、社交、信息检索等）。
- SWE-bench：真实 GitHub issue → 自动修 bug/添功能 → 测试验证。
- AgentBench：覆盖代码、游戏、网页、工具使用等多维度。
- ToolBench/TaskBench：评估工具使用和任务分解能力。

### 6.7 评估 Agent 应关注哪些过程指标？

- 效率：任务完成耗时、总 token 消耗、工具调用次数。
- 成本：LLM API 费用、工具调用成本。
- 鲁棒性：失败后恢复率、异常处理能力、不同输入变体的表现一致性。
- 完成率：是否过早终止、是否陷入死循环。

### 6.8 什么是红队测试？

用对抗性方式系统性地测试 LLM/Agent 的安全漏洞和偏见。模拟攻击者尝试让模型产生有害/违规输出，发现模型边界和脆弱点。是上线前必需的安全评估环节。

### 6.9 如何进行客观一致的人工评估？

- 明确定义评估准则和打分标准（Rubric），附带例子。
- 多人标注取一致性（Cohen's Kappa / Krippendorff's Alpha）。
- 盲评 + 随机顺序呈现（消除位置偏见）。
- 定期校准会，统一标注者对边界 case 的理解。

### 6.10 部署后如何持续监控 LLM/Agent 表现？

- 核心指标监控：延迟（P50/P95/P99）、错误率、token 消耗、用户反馈。
- 质量漂移检测：定期用固定评测集回归；线上抽样人工评估；Badcase 追踪闭环。
- 日志与 Trace：全链路日志记录，便于排查和归因。
- 告警与降级：关键指标异常自动告警；预备降级策略（切换备选模型/规则兜底）。
